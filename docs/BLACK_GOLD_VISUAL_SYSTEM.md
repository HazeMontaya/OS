# OS Black–Gold Visual System v2

Status: **canonical visual contract** for the desktop experience.

This document defines the visual identity, interaction language, material system, spatial semantics and quality rules for OS. The goal is not a decorative sci-fi dashboard. OS must read as a precise, high-end cognitive instrument whose visuals are generated by real state, real activity and real system relationships.

## 1. Identity principles

1. **Obsidian first.** The interface begins almost black. Darkness is functional negative space for cognition, depth and focus.
2. **Gold means information energy.** Gold is not ornament. Brightness, warmth, density and motion communicate relevance, activity, confidence and focus.
3. **State before spectacle.** Every animated signal should correspond to runtime state, user interaction, graph structure or a clearly identified ambient layer.
4. **Spatial hierarchy before panel hierarchy.** The 3D cognition field is the primary stage. 2D panels are instruments that appear around it, not the product itself.
5. **Controlled complexity.** Dense information is acceptable when semantic zoom, contrast, grouping and progressive disclosure preserve orientation.
6. **One brand, several calibrated expressions.** Themes may tune black and gold values but cannot change the semantic grammar.
7. **No legacy cyan language.** Cyan/blue glass is not part of the OS v2 identity. Exception: external content that genuinely carries that color.

## 2. Theme family

The theme engine lives in `@os/design-system` and exposes four calibrated variants.

| Theme | Purpose |
| --- | --- |
| `OBSIDIAN_GOLD` | Default. Near-black obsidian with warm architectural gold. |
| `IMPERIAL_BLACK` | Higher contrast and stronger royal-gold signals. |
| `CARBON_BRASS` | Lower-fatigue technical mode for dense, long sessions. |
| `NOIR_CHAMPAGNE` | Pale champagne highlights for cinematic/presentation states. |

The canonical default is `OBSIDIAN_GOLD`.

### Core palette

- Canvas: `#030303`
- Surface: `#080706`
- Raised surface: `#0f0c08`
- Soft surface: `#151006`
- Gold: `#d7b35a`
- Bright gold: `#f4d887`
- Soft gold: `#ffe8ae`
- Bronze: `#8f6730`
- Primary text: `#f4efe4`
- Muted text: `#b9aa8a`
- Faint text: `#776d5a`

Do not hard-code new UI colors when a semantic theme token exists.

## 3. Semantic cognition colors

Within the black–gold family, cognitive categories remain distinguishable through controlled gold temperature/value rather than unrelated rainbow colors.

- self/core → brightest champagne-gold
- actor → muted pale gold
- episodic memory → aged amber
- semantic memory → clear warm gold
- stable memory → pale stable gold
- model → high-energy light gold
- agent → active gold
- tool → darker mechanical bronze-gold
- goal → pale aspirational gold
- project → structural gold
- historical relation → desaturated bronze
- danger/destructive state → restrained burnt orange/red

Color alone must never be the sole state carrier; geometry, opacity, label, motion or pattern must reinforce the meaning.

## 4. Logo and brand mark

The OS mark is an adaptive cognitive-core symbol:

- faceted outer containment shell
- segmented orbital ring
- central diamond / processing core
- axial guides
- luminous central point

The mark exists as reusable SVG (`public/os-mark.svg`, `brand/OsMark.tsx`) and native Windows icon assets.

### Scaling rules

- 16–32 px: prioritize silhouette, center core and outer containment; micro-detail must not be required for recognition.
- 48–128 px: full segmented orbital geometry may be visible.
- 256 px and above: additional tonal depth is acceptable, but the silhouette remains unchanged.
- UI mark must use the same geometry as application/Windows branding.

Do not revert to a generic glowing dot as the primary brand mark.

## 5. Material language

OS uses several coordinated material classes instead of one universal glass card.

### Abyss
The spatial background. Nearly black, fogged, extremely low reflectance.

### Obsidian instrument
Primary panels: high-opacity black, thin gold boundary, restrained blur, very low saturation.

### Signal glass
Temporary hover/focus readouts. More transparent and lighter than permanent instruments.

### Gold trace
Active relations, selected boundaries, focus rings and execution flows.

### Bronze history
Historical, inactive or low-priority information. Lower luminance and contrast.

### Containment field
Risk/security/permission boundaries. Geometry and line behavior matter more than fill color.

## 6. Typography

Preferred Windows-first stack:

- UI/display: Segoe UI Variable → Inter → Segoe UI
- technical/telemetry: Cascadia Code → JetBrains Mono → Cascadia Mono

Rules:

- Normal readable body copy should not rely on 7–9 px text.
- 7–9 px may be used only for secondary instrumentation where loss does not prevent task completion.
- Long prose/output uses a readable line height around 1.6–1.75.
- Telemetry uses uppercase sparingly and consistent tracking.
- Display headings are light/medium weight, not faux-bold HUD typography.

## 7. Spatial cognition language

The Void represents canonical OS state; it is never a fictional animation detached from state.

### Nodes
Importance controls visual scale. Confidence affects stability/opacity. Category controls gold temperature and shape behavior.

### Relations
Current relations use gold signal lines. Historical relations use desaturated bronze. Active cognitive phases may animate trace packets only over relations relevant to that phase.

### Clusters
Clusters emerge at larger camera radii and collapse into individual nodes as semantic zoom advances.

### Semantic zoom
Canonical levels:

`UNIVERSE → CLUSTER → NETWORK → DETAIL → INSPECT`

Each level changes object budgets and information representation, not merely camera magnification.

### Motion
Motion is event-driven where possible. Ambient motion must remain low amplitude and explicitly bounded. Reduced-motion disables nonessential movement.

## 8. Workspace visual identities

All workspaces use the same black–gold language but different projection filters, camera modes and spatial densities.

- Cognitive Core — live cognition and active context
- Knowledge Constellation — entities, concepts, relations, projects
- Memory Archive — episodic/semantic/stable memory
- Agent Operations — agents, models, tools, plans and traces
- Developer Matrix — IPC, providers, execution and renderer diagnostics
- System Fabric — capabilities, tools, devices and process boundaries
- Configuration Chamber — theme/quality/settings focus
- Automation Circuit — trigger-to-action workflow topology

Workspaces must not become unrelated mini-app themes.

## 9. 2D shell rules

- Top bar: status/brand/instrumentation only.
- Workspace dock: navigation, not a conventional application sidebar.
- Command field: persistent primary interaction surface.
- Analytics: dense 2D telemetry via ECharts; it must use live state and theme tokens.
- Inspector: contextual properties/relations for selected spatial objects.
- Settings: effective values and renderer controls; controls must affect real runtime behavior when exposed.

## 10. Effects budget

Effects are quality-scaled, never unconditional.

- Bloom: gold signal only; avoid washing text or panels.
- Fog: depth cue and cluster separation.
- Grain: subtle cinematic layer, user-disableable.
- Scan/grid: very low contrast; never interfere with text.
- Shadows: optional and profile-dependent.
- Blur: reserved for instrument separation; never the sole visual identity.

## 11. Accessibility

- Respect `prefers-reduced-motion` and OS reduced-motion setting.
- Provide visible keyboard focus.
- Increased-contrast mode strengthens borders and critical text.
- State must remain interpretable without color alone.
- Text contrast takes precedence over atmosphere.

## 12. Quality bar

A change is visually acceptable only if:

1. it uses semantic tokens rather than arbitrary cyan/blue or unrelated colors;
2. it preserves hierarchy at 1040×680 minimum window size;
3. the primary task remains readable at 100% Windows scaling;
4. motion has a state/interaction rationale;
5. the renderer remains bounded by a quality profile;
6. preview/fallback mode does not invent telemetry;
7. a degraded GPU path remains usable;
8. the OS logo and black–gold identity remain consistent from native icon through spatial shell.
